# Dead-code check (knip)

This repository runs [knip](https://knip.dev) to stop dead code from
accumulating: files that nothing references, `package.json` dependencies that
nothing imports, and imports of packages that are not declared in
`package.json`.

CI runs `yarn knip:check` in the **Repository health checks** job (alongside
depcheck and the yarn audit), and fails when:

- the knip report contains a finding that is **not** in the committed baseline
  (`development/knip-baseline.jsonc`), or
- a baselined finding **no longer** appears in the knip report, because the
  baseline must be shrunk whenever its findings are fixed.

The baseline is the work queue: it lists known dead code so that CI only gates
on _new_ findings, and each entry waiting in it can be cleaned up by its
owning team over time.

## Commands

| Command                         | What it does                                                                                                                                   |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `yarn knip:check`               | Run knip and compare against the baseline. Fails on new findings, and on findings that were fixed but are still baselined. Same check CI runs. |
| `yarn knip:update`              | Rewrite the baseline from the current report. **Refuses to grow** the baseline unless `--allow-grow` is passed.                                |
| `yarn knip:update --allow-grow` | Rewrite the baseline, allowing new entries. Only for when growing the baseline is genuinely intended.                                          |
| `yarn knip:codeowners`          | Print the current findings grouped by their `.github/CODEOWNERS` team — the work-queue view used to hand findings to owning teams.             |
| `yarn knip`                     | Run knip directly with the default reporter (respects `knip.config.ts`).                                                                       |

## What is checked (phase 1)

Only three issue types gate CI:

- **Unused files** — files nothing imports and no entry point reaches.
- **Unused dependencies** — packages declared in `package.json` that nothing
  imports.
- **Unlisted dependencies** — packages imported by source code but not declared
  in `package.json`.

Everything else (unused exports, unused types, duplicate exports, enum
members, unresolved imports, binaries, cycles, ...) is turned off in
`knip.config.ts` and can be enabled incrementally in later phases.

## Working with the baseline

The baseline file (`development/knip-baseline.jsonc`) is machine-generated by
`yarn knip:update`; do not edit it by hand. Each entry is a stable key of the
form `<type>|<file>|<symbol>` with **no line numbers**, so entries survive
unrelated edits and the file diffs cleanly:

```text
files|app/scripts/runtime-cjs.ts
dependencies|package.json|base32-encode
unlisted|app/scripts/metamask-controller.test.js|ulid
```

When CI fails with new findings:

1. **Fix the finding** (preferred): delete the dead code, or declare the
   missing dependency.
2. **Suppress it** if it is intentional: add it to `entry`, `ignore` or
   `ignoreDependencies` in `knip.config.ts` — always with a reason comment.
   Intentional findings should not live in the baseline.
3. Only if growing the baseline is genuinely intended (e.g. the finding is
   real dead code but cleanup is being tracked for another team), run
   `yarn knip:update --allow-grow` and commit the change.

When CI fails because baselined findings disappeared (thank you for fixing
them!), run `yarn knip:update` (this shrinks the baseline — growth is still
refused) and commit the change.

## Configuration

`knip.config.ts` declares the intentional entry points that knip cannot
discover on its own — the extension's real roots are referenced from HTML
pages and the extension manifests, which knip does not parse:

- the HTML pages in `app/html` and the scripts they reference (background,
  UI, offscreen, cashtag widget), the manifest-referenced content scripts and
  the MV3 service worker;
- storybook (` .storybook`), the build/tooling trees (`development`),
  devcontainer scripts, E2E suites (`test/e2e`), integration tests, test
  helpers/mocks and `.github/scripts`;
- `**/*.proof.ts` compile-time type assertions, which are exercised by
  `yarn lint:tsc` through tsconfig inclusion rather than imports.

Stylesheets are out of scope for this check: they are aggregated through
`ui/css/index.scss` (referenced from `app/html/partials/partial-head.html`)
and webpack, and are verified by `yarn lint:styles` instead.

Dependencies that are used only through mechanisms knip cannot see (HTML
`<script src>`, Babel/Jest transform strings, CSS `url()` fonts, transitive
packages referenced by name) are listed in `ignoreDependencies` with a reason
comment. That list should stay consistent with `.depcheckrc.yml`, which
tracks the same class of blind spots for depcheck.

## Notes

- Runtime is a few seconds locally (and under a minute on a cold CI cache),
  so it fits inside the existing Repository health checks job.
- `yarn knip --reporter codeowners` is knip's built-in codeowners grouping,
  but in knip 6.48 it currently crashes when the report contains unused-file
  findings (the only kind this check reports); `yarn knip:codeowners` provides
  the same grouping from the JSON report instead. Revisit once knip ships a
  fixed release.
- The check mirrors the same guardrail introduced in
  [MetaMask/metamask-mobile#40535](https://github.com/MetaMask/metamask-mobile/pull/40535).
