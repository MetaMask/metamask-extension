# Dead-code check (knip)

This repository runs [knip](https://knip.dev) to stop dead code from
accumulating: files that nothing references, `package.json` dependencies that
nothing imports, and imports of packages that are not declared in
`package.json`. CI runs `yarn knip:check` in the **Repository health checks**
job (alongside depcheck and the yarn audit).

The check gates on the diff against the committed baseline
(`development/knip-baseline.jsonc`), not on the raw knip report. The baseline
is the work queue: it lists known dead code so CI only fails on _new_
findings, and each waiting entry can be cleaned up by its owning team over
time. It mirrors the guardrail introduced in
[MetaMask/metamask-mobile#40535](https://github.com/MetaMask/metamask-mobile/pull/40535).

Phase 1 gates only on unused **files**, unused **dependencies** and
**unlisted** dependencies; everything else (unused exports/types, duplicates,
unresolved imports, binaries, cycles, ...) is off in `knip.config.ts` and can
be enabled incrementally in later phases.

## Commands

| Command                         | What it does                                                                                                                                                                   |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `yarn knip:check`               | Run knip and compare against the baseline; fails on new findings and on baselined findings that no longer appear (the baseline must be shrunk after fixes). Same check CI runs. |
| `yarn knip:update`              | Rewrite the baseline from the current report; refuses to grow it unless `--allow-grow` is passed.                                                                               |
| `yarn knip:update --allow-grow` | Rewrite the baseline, allowing new entries — only when growing it is genuinely intended.                                                                                        |
| `yarn knip:codeowners`          | Print the current findings grouped by `.github/CODEOWNERS` team — the work-queue view used to hand findings to owning teams.                                                    |
| `yarn knip`                     | Run knip directly with the default reporter (respects `knip.config.ts`).                                                                                                        |

## Working with the baseline

The baseline is machine-generated by `yarn knip:update`; do not edit it by
hand. Each entry is a stable `<type>|<file>|<symbol>` key with no line
numbers (e.g. `files|app/scripts/runtime-cjs.ts`), so entries survive
unrelated edits and the file diffs cleanly.

When CI fails with new findings: fix them (preferred), or — if they are
intentional — suppress them in `knip.config.ts` (`entry`, `ignore` or
`ignoreDependencies`, always with a reason comment; intentional findings
should not live in the baseline). Only if growing the baseline is genuinely
intended, run `yarn knip:update --allow-grow` and commit the change.

When CI fails because baselined findings disappeared (thank you for fixing
them!), run `yarn knip:update` — it shrinks the baseline, and still refuses to
grow it — then commit the change.

## Configuration

`knip.config.ts` declares the intentional entry points that knip cannot
discover on its own — the extension's real roots are referenced from HTML
pages and the extension manifests, which knip does not parse: the scripts
behind `app/html` (background, UI, offscreen, cashtag widget), the
manifest-referenced content scripts and MV3 service worker, storybook,
`development` tooling, `test/e2e`, `.github/scripts` and the `*.proof.ts`
compile-time type assertions (exercised by `yarn lint:tsc`, never imported).

Stylesheets are out of scope: they are aggregated through `ui/css/index.scss`
(referenced from `app/html/partials/partial-head.html`) and webpack, and are
verified by `yarn lint:styles` instead. Dependencies used only through
mechanisms knip cannot see (HTML `<script src>`, Babel/Jest transform strings,
CSS `url()` fonts, transitive packages referenced by name) are listed in
`ignoreDependencies` with a reason comment; that list should stay consistent
with `.depcheckrc.yml`.

## Notes

Runtime is a few seconds locally and on CI, so the check fits inside the
existing job. knip's built-in `--reporter codeowners` currently crashes on
unused-file findings in knip 6.48; `yarn knip:codeowners` provides the same
grouping from the JSON report instead. Revisit once knip ships a fixed
release.
